# Country Search

Живой поиск стран по английскому названию через публичный API [countries.dev](https://countries.dev). Пользователь печатает, приложение само отправляет запрос и показывает карточки стран. Главная техническая задача проекта: устаревший ответ не должен перезаписывать актуальный, поэтому предыдущий запрос реально отменяется через `AbortController`.

Проект написан на TypeScript без фреймворков и бандлера: `tsc` собирает ES-модули, `index.html` подключает их через `<script type="module">`. Это учебное задание RS School.

## Реализовано

- Поиск по мере ввода: каждое изменение поля сразу отменяет предыдущий запрос, сам запрос уходит после паузы 300 мс.
- Пустой ввод не отправляет запросов и очищает список.
- Состояния: подсказка, загрузка, результаты, «ничего не найдено», ошибка с кнопкой `Retry`.
- Карточка страны: флаг, название, столица, регион, население.
- Подробности страны по клику на карточку или кнопке `Details` в нативном `<dialog>`: название и флаг, краткое описание из имеющихся фактов, родное название, регион, субрегион, столица, население, площадь, языки, валюты, границы (коды alpha-3), статус независимости. Дополнительных запросов к API не делается.
- Адаптивная вёрстка от 320 px, видимый фокус, сообщения статуса в области `aria-live`.
- Тесты на Vitest, ESLint, Prettier, хуки Husky.

## Требования

- **Node.js**: в `package.json` указано `>=24`, разработка и проверки выполнялись на Node 24.6. Ограничения установленных зависимостей: Vitest 5.1 — `^22.12 || ^24 || >=26`, ESLint 10.15 — `^20.19 || ^22.13 || >=24`, lint-staged 16.4 — `>=20.17`. Нечётные версии (например, 25) Vitest не заявляет.
- **npm** с поддержкой `npm ci` (проверено на npm 11.5).
- Современный браузер с поддержкой ES-модулей, `fetch`, `AbortController` и `<dialog>`.
- Доступ к интернету: приложение обращается к `https://countries.dev` напрямую из браузера (API разрешает CORS).

## Локальный запуск

Модули нельзя открыть через `file://`: браузер блокирует загрузку ES-модулей с такого адреса. Нужен любой статический HTTP-сервер, запущенный из корня проекта после сборки:

```bash
npm run build
python3 -m http.server 8080 --bind 127.0.0.1
```

Затем откройте `http://127.0.0.1:8080/index.html`. Сервер не входит в зависимости проекта; подойдёт любой другой статический сервер. Каталог `dist/` не хранится в репозитории, его создаёт сборка. В `index.html` подключаются `./styles.css` и `./dist/main.js`.

## Сборка публичной папки `site`

```bash
npm run build:site
```

Команда сначала удаляет только сгенерированные каталоги `dist/` и `site/`, затем выполняет `npm run build` (компиляция TypeScript), затем `scripts/build-site.mjs` копирует в `site/` только `index.html`, `styles.css` и `dist/`. Исходники, тесты, `node_modules` и конфигурация в `site/` не попадают. Путь `./dist/main.js` в HTML сохраняется. Папка `site/` создаётся заново при каждой сборке и не хранится в репозитории (как и `dist/`).

Локальная проверка именно публикуемого содержимого:

```bash
cd site
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8080/index.html`. Файлы вне `site/` (например, `/package.json` или `/src/main.ts`) по этому адресу недоступны.

В `netlify.toml` описаны команда сборки (`npm run build:site`), публикуемая папка `site` и Node 24. **Сервис Netlify не подключён, деплой не выполнен**, ссылки на опубликованное приложение нет.

## API countries.dev

Запрос: `GET https://countries.dev/name/{query}`. Поиск идёт по английскому названию страны, подстрока без учёта регистра; кириллический запрос вернёт «ничего не найдено». Запрос обрезается по пробелам и кодируется через `encodeURIComponent`. Пустой запрос не отправляется.

- `200`: массив стран. Тело проверяется на границе как `unknown`, затем преобразуется в данные карточки.
- `404`: совпадений нет. Это не ошибка, показывается «Nothing found».
- другой неуспешный статус: ошибка `HttpError` со статусом.

## Ошибки, таймаут и отмена

- **Отмена** (новый ввод, очистка поля, закрытие страницы) — не ошибка, пользователю ничего не показывается.
- **Таймаут** 8 секунд на запрос вместе с чтением тела ответа: сообщение «The server took too long to respond».
- **Сеть** (обрыв, DNS, CORS и подобное): сообщение «Could not reach the server».
- **HTTP-ошибка** (не 404): сообщение с кодом статуса.
- Кнопка `Retry` повторяет именно последний запрос, завершившийся ошибкой.

Различение выполняется по типу и имени ошибки (`HttpError`, `AbortError`, `TimeoutError`), а не по тексту сообщения. Подробности и обоснование: [DESIGN.md](DESIGN.md).

## Управление с клавиатуры

- `Tab` переводит фокус от поля поиска к кнопкам `Details` карточек.
- `Enter` или `Space` на кнопке открывает подробности; клик по любой части карточки делает то же самое.
- Внутри окна фокус сразу на кнопке `Close`; `Escape` или `Close` закрывают окно, и фокус возвращается на кнопку, которой оно было открыто.

## Ограничения

- Нет кэша ответов и истории запросов, повторный одинаковый запрос снова идёт в сеть.
- Приложение не работает без доступа к `countries.dev`.
- Подробности открываются только для уже полученных результатов.
- У API нет поля с описанием страны; краткое описание в окне подробностей составляется только из названия, родного названия, региона и субрегиона.
- Интерфейс только на английском.
- **Деплой пока не выполнен** (Netlify не подключён), ссылки на опубликованное приложение нет.

Ограничения проверки (что не подтверждено) перечислены в конце [DESIGN.md](DESIGN.md).
